# 首篇文章重置计划（控制器用）

日期：2026-07-20 CST  
性质：仅规划；不沿用旧候选，不写稿、不渲染、不发布，也不作最终验收决定。

## 0. 先纠偏

旧 E1/D1 只能作为失败样本：其证据包创建于 2026-07-17、来源最晚为 2026-07-12；其 `draft.md` 是固定五标题、逐行“编辑提问”和 claim ledger 英文原句的组合，不是普通读者可读的中文文章。`validate_draft.py` 又把这三种形态写成通过条件。这些约束没有 canonical 文档依据，必须从新路径中删除，不能把旧包换日期后复用。

另有两个边界必须显式保留：

1. `docs/daily-article-group-v1.md` 的结构化证据门用于证明事实边界，不能替代编辑质量判断；其中“标题承诺、钩子、节奏、递进、收束均须可解释”不等于固定标题/段落模板。
2. 当前 `scripts/graphite_minimal_external_adapter.py` 自述“不含 upstream template/component/CSS”，并只证明 validator compatibility、明确“不证明微信粘贴”。它不能单独被称为 canonical Graphite 成稿能力；未找到并验证权威 Graphite 资产时必须 `template-blocked`。

## 1. Canonical 创作要求与不可让步项

- 账号方向：借影视内容讲人物命运、观众情绪和现实处境；不做纯快讯、纯数据、纯行业分析，不写情感号鸡汤。
- 文风：克制白描、高密度、不注水；避免宏大叙事、AI 套话、营销号口吻。
- 具体中心：文章持续回到片名、人物、桥段、主创选择或可核验细节，热点只作入口。
- 读者价值：立项时能说明读者为何点击、看完、转发；这些是内部判断，不得以“爆款逻辑/传播公式/读者痛点”等后台语言进入正文。
- 完整交付：最终候选必须有完整、普通可读的 Markdown 正文；候选页、白名单、claim ledger、review 页面都不是文章。
- 事实边界：事实、具名观点、编辑推论必须可区分；争议、否认、隐私和冲突按来源规则处理；不能把抽样评论写成共识。
- 默认长度 1500–2200 个中文字符；偏离只能由编辑基于具体题材说明理由，不能靠填充或删掉关键证据达标。
- 最终候选交付应含 Markdown、Graphite 美化 HTML 与本地可打开路径；但 Graphite 资产不可验证时只保留 draft 和 `template-blocked`，不得伪造 HTML 或称 final。
- final 只表示包内门禁通过，不表示发布批准；发布、上线、Cron 和阶段晋级均留给控制器。

明确废除三项杜撰限制：

1. 不要求固定五个标题或任何有限标题集合；小标题数量和措辞由叙事需要决定。
2. 不要求正文只能由问题句组成；正文必须是自然连贯的中文叙事/评论，提问只在确有修辞作用时使用。
3. 不要求 claim ledger 原句逐字进入正文；ledger 是后台溯源工具，正文应在不改变事实含义的前提下自然转述，并保留必要归属。

## 2. 最小正确流水线

1. **当日来源发现**：从 2026-07-20 CST 重新搜索；按同事件/同角度去重，记录发布时间、访问时间、发布方、作者/机构、URL、定位、角色和 independence group。旧 E1/D1 不进入候选集合。
2. **证据包**：为一个候选建立来源快照和 claim 映射；事实/引语/数字/时间判断逐项有 `claim_id → source_id → 摘录/定位`，同时列拒绝主张、冲突、访问/许可状态和来源限制。
3. **编辑 brief**：内部一页即可，写清具体人物/作品/事件、核心矛盾、读者心理、点击钩子、看完理由、转发动机、预期收束、不可声称事项。brief 不得直接拼进正文。
4. **Markdown 普通成稿**：先按读者语言完成 1500–2200 中文字符的完整文章；结构服从叙事，不服从 validator 模板；事实自然转述，必要观点明确归属。
5. **独立内容/来源复核（Sol）**：直接读 canonical 文档、证据包、brief 和 Markdown，检查具体中心、来源兑现、事实/观点/推论边界、标题与峰终、后台腔、原创性及遗漏反证；只给 `approve / needs_changes / evidence_insufficient`，不代写、不授权发布。
6. **Graphite HTML**：仅当 Markdown 通过独立复核后，发现并验证 canonical Graphite 资产的路径、版本/哈希、可渲染性和微信粘贴样例，再由已通过的 Markdown 单向生成 HTML；HTML 不得反向改写内容。
7. **最终门禁**：机器复跑证据、状态、哈希、净化、正文一致性；人工复看标题、开头、正文推进、结尾、移动端阅读和微信受控预览。通过只形成“供控制器验收”的 ArticleBundle。

## 3. 机器检查与编辑判断的边界

### 机器可验证

- 文件/字段是否存在，JSON 是否可解析，时间是否带时区；URL 能否回访，页面是否为验证码/安全页/抓取异常。
- 来源发布时间、访问时间、独立组数量、同稿/转载归并、24/72 小时时窗及强度算分。
- 每个事实/引语/数字/时间判断是否有 claim 映射、摘录和定位；否认/冲突是否同段标记要求被记录。
- 中文字符数、禁用后台词扫描、危险 HTML 标签/属性/协议、外链 CSS、script/iframe/form、Markdown 与 HTML 正文一致性。
- Graphite 路径、版本/commit、哈希、渲染器返回码、产物哈希和状态不得误标 final。

### 必须由人/独立编辑判断

- 选题是否真正讲人物命运、观众情绪或现实处境，而非把热点换一种说法。
- 标题是否具体、有准确钩子且不标题党；Hook 是否立即建立事件与利益/情绪冲突。
- 正文是否自然、清楚、有细节、递进和人味；推论是否合理且未越过证据。
- 结尾是否回到人物或处境，留下读者可认领的态度，而非空泛启示。
- 转述是否原创、是否保留来源含义、是否把宣传材料或零散评论膨胀成共识。
- Graphite 版式是否真的适合移动端与微信阅读。

机器不得以“出现五个标题”“每行是问句”“逐字命中 ledger”代理上述判断。

## 4. 来源新鲜度与独立性验收

以执行时刻为基准，而不是文件创建日：

- 触发候选的事件/报道信号须在最近 24 小时内；25–72 小时材料只能作背景并降一级；超过 72 小时不得触发。旧闻“今天重新访问”不等于今天的新鲜信号。
- 强项：按 v1 规则达到至少 4 分、至少 2 个独立组且含一手确认源；中项至少 2 分且至少 2 个独立组。只有一个独立组或 0 分发现源不得进入首篇生产。
- 同稿、转载、聚合、同机构或共用原始材料合并为一个 independence group；托管平台不能把原始媒体稿变成第二个独立来源。
- 一手回应/原始材料与具名独立报道分开计角色；宣传活动稿、片方口径和抽样观众发言只能支撑其实际表述，不能支撑质量或共识。
- rumor/privacy 至少两个独立公开确认源；有否认/澄清/关键冲突时，同一主张附近必须呈现。无法消解则 `EVIDENCE_CONFLICT`，不自动裁决。
- 任一核心来源不可访问、无可靠定位、日期不明或许可边界未记录，证据包不得进入写稿。

## 5. 标题、Hook、正文、结尾的验收

- **标题**：优先出现具体人物、片名或事件，并由反差、争议、悬念、利益或失衡感提供钩子；承诺必须被正文和证据兑现。拒绝“问题不只……/别只……/真正的问题不是……”等后台分析骨架，但不设固定句式白名单。
- **Hook（前 200 字）**：直接交代谁出了什么事、谁与谁发生冲突、谁的利益/命运被改写，以及读者为何要继续；不得先写作者元叙事或长篇背景。
- **正文**：围绕一个可复述的中心推进，持续回到具体角色、桥段、主创或核验事实；不是剧情复述，也不是素材价值/传播逻辑讲解。事实、具名观点和编辑推论在语义上清楚分层，不要求显式 claim 标签出现在读者稿。
- **结尾**：回到一个人、一种处境或观众终于看见的东西，形成态度/命运/现实处境的峰值；禁用“值得深思”“给我们启示”等空泛收束。是否使用问句由文章决定，不设硬性句式。

## 6. 精确的最小测试与复核计划

### A. 来源/证据（写稿前，全部通过）

1. 记录执行时刻（CST）并自动计算每个来源年龄；构造 24h、25–72h、>72h 三个边界样例，确认分别为触发、背景降级、拒绝。
2. 对候选重新访问全部 URL；验证码/安全页/异常页样例必须被拒绝为证据。
3. 以一个转载/同稿对照样例验证 independence group 合并；重算分数，确认强项必须“≥4 分、≥2 独立组、含一手”。
4. 随机抽核全部核心 claim（首篇规模小，实际即全量）：每项事实/引语/数字/时间判断都能从映射跳到来源摘录与 locator；加入一个无映射事实，门禁必须失败。
5. 若有冲突/否认或 rumor/privacy，加入缺少同段披露/第二独立源的反例，门禁必须失败；若无，则明确记录 N/A，不伪造测试结论。

### B. Markdown（渲染前）

1. 自动：1500–2200 中文字符、后台禁词扫描、无 claim 标签/brief 字段泄漏、引用与链接可定位、状态仍为 draft。
2. 负向回归：三份坏稿——固定五标题空壳、全问句填充、ledger 原句堆叠——即使字数和 claim 映射齐全，也不得被内容复核批准。
3. 独立 Sol 全文复核：逐项检查标题、前 200 字、具体中心、证据兑现、归属、推论、段落推进、结尾、原创性；发现项必须给目标、证据、失败模式、最小修复条件和重检证据。

### C. HTML/最终包（Markdown 获得独立复核证据后）

1. Graphite 依赖：核验 canonical 路径、origin/版本/哈希、实际渲染；缺失或不匹配必须 `template-blocked`，不得生成 final HTML。
2. 自动净化：结构可解析；script、事件属性、iframe、form、外链 CSS、危险 URL 和不可控嵌入反例均失败。
3. 一致性：抽取 HTML 可见正文与获准 Markdown 比较，标题、段落、引语、链接不得增删改事实；产物哈希入 manifest。
4. 人工受控预览：移动端宽度及微信粘贴环境检查标题层级、留白、强调、引用、链接/图片归属；当前 adapter 的 validator 输出不能替代该证明。
5. 最终状态检查：所有门通过才可标“供控制器验收”；仍保持 `publish_authorized=false`，不触发发送、Cron 或微信发布。

## 7. 停止条件与 fallback

- 24 小时内没有满足强项规则的候选：停止首篇生产，交 `NO_FRESH_STRONG_CANDIDATE`；不拿 25–72 小时背景或旧 E1 顶替。
- 来源无法回访、独立性不足、核心 claim 无定位、冲突无法按规则呈现：停止于 evidence；保留缺口，不写稿。
- brief 说不清读者为何点/看完/转发，或只能形成快讯/行业分析：候选降级或放弃，回到发现阶段。
- 两轮有界修订后内容复核仍为 `needs_changes`，或原始材料/证据缺失为 `evidence_insufficient`：停止，不进入 HTML。
- canonical Graphite 资产、微信样例或受控预览不可验证：`template-blocked`，只交已复核 Markdown draft 与缺口；不得用本地 adapter 冒充 Graphite 完成交付。
- HTML 与 Markdown 不一致、净化失败、预览不可读：保留 Markdown，HTML 非 final；不得静默降级。
- 任何 approve 都只是控制器证据，不是发布、发送、上线或阶段晋级授权。

## 8. 唯一首个可执行 Terra 卡

**标题：** `Terra：2026-07-20 当日强项发现与 evidence pack（仅 E1）`

**范围：** 从 2026-07-20 CST 的实时公开来源重新发现一个影视/娱乐当日强项；不得打开旧 E1/D1 作为候选输入，不写 brief、正文或 HTML，不改代码/Cron，不发布。

**验收：**

- 交一个候选 evidence pack（JSON + 人读摘要），记录执行时刻、来源角色、publisher/author、published_at、accessed_at、URL、摘录、locator、independence_group、访问/许可状态、风险/否认状态。
- 触发信号 ≤24h；重算得分 ≥4、至少 2 独立组且含一手；同稿/转载已归并。
- 核心 claim 全量映射到来源；事实、具名观点、宣传口径和编辑推论分开；列出拒绝主张与证据限制。
- 给出 URL 可回访及 24/72h、同稿归并、缺失映射三个负向检查的真实输出。
- 状态只能为 `evidence_ready_for_brief` 或明确失败码，`publish_ready=false`。

完成后才由控制器创建独立 Sol 来源复核卡；未通过不得创建写稿卡。

## 9. 最短执行顺序

Terra 当日发现/E1 → Sol 独立来源复核 → Terra 编辑 brief → Terra 普通 Markdown → Sol 内容/来源复核 → Terra Graphite HTML → Sol 最终包复核 → 控制器决定是否接受；任何一步失败即按本计划停止或回退，不跨门补做。
