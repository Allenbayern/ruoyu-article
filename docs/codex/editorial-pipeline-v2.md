# 若雨随影文章组—定向抓爬协作流程 v2

更新：2026-09-06。本文明确文章组与抓爬任务的协作边界，供项目内任务使用。它不替代来源审计、隐私边界、发布授权和机器契约。

## 一、总原则

文章组决定写什么，抓爬任务决定如何把这篇文章所需的材料找齐。抓爬任务不能自行改变核心问题、扩大题材、替换人物，也不能因为搜到另一个更热的事件就改题；发现原题不可写时，应退回并说明原因。

文章组最终写标题和正文。抓爬任务交付材料包、出处、证据缺口和淘汰记录，不交成稿，不把材料包当成事实自动通过。

## 二、状态与责任

| 状态 | 进入条件 | 负责人 | 可执行动作 |
|---|---|---|---|
| `idea` | 只有一个模糊想法或热榜信号 | 文章组 | 补写核心问题，不创建正式抓爬任务 |
| `precheck` | 已写对象、读者、问题和范围 | 文章组 | 查历史重复、风险和可写性 |
| `approved` | 选题预检通过，写作需求明确 | 文章组 controller | 冻结题目与材料需求，创建抓爬任务 |
| `researching` | 抓爬任务已收到 approved 卡 | 抓爬任务 | 按材料需求搜索、抓取、核验和筛选 |
| `material_ready` | 材料包达到最低验收条件 | 抓爬任务 | 交回材料包，标出缺口和禁写项 |
| `writing` | 文章组接受材料包 | 文章组 | 写标题、正文并绑定证据 |
| `review` | 成稿和证据已绑定当前版本 | 文章组复核 | 查事实、标题兑现、自然表达和交付条件 |
| `returned` | 材料不足、题目漂移或成稿不兑现 | 发起方记录 | 只补指定缺口、缩小题目或换题 |
| `closed` | 交付完成或明确终止 | 文章组 controller | 记录结果，决定是否进入案例升级流程 |

只有文章组 controller 能把 `precheck` 改为 `approved`、批准换题、接受 `material_ready` 或关闭任务。抓爬任务可以提出 `return_reason`，不能自行批准换题。

## 三、选题确认卡

创建抓爬任务前必须有一张版本化选题卡，至少包含：

- `topic_id`、版本、发起时间和负责人
- 具体影视对象、人物或事件
- 一个核心阅读问题
- 目标读者和预计阅读收益
- 冲突、关系、选择或现实映射
- 文章类型：资讯、作品评论、人物评论、行业观察等
- 当前触发或常青理由
- 历史同作品、同事件簇和相近标题检查
- 必须抓取的材料类型和关键实体
- 不允许扩展的范围、隐私/司法/版权风险
- 通过标准和截止时间

“某话题很热”“写某部电影”“搜一下观众反应”都不能单独作为 approved 卡。

## 四、抓爬任务的材料需求

任务卡把需求拆成四层：

1. **正文事实**：人物、作品、事件、时间线、具体动作和结果。
2. **行业背景**：只抓能解释核心问题的机制、数据或历史，不做无边界行业综述。
3. **观众反应**：区分单人评论、同类观点、平台讨论趋势；记录样本来源、时间和代表性限制。
4. **复核事实**：关键数字、引语、争议和因果关系至少寻找第二来源；找不到时标记缺口，不用搜索摘要填补。

每条材料都要记录 `material_id`、摘要、来源、发布时间/抓取时间、原文定位、证据等级、可支持的句子或段落，以及不得推导出的结论。发现信号、社交平台帖子和搜索摘要默认是线索，不是强事实证明。

## 五、材料包最低验收

`material_ready` 必须同时满足：

- 核心问题没有被抓取过程改写；
- 至少有两类不同的具体支撑，其中一类能直接支撑正文开头；
- 关键事实有权威或可复核来源和定位；
- 事实、当事人说法、观众观点和推断分栏；
- 观众反应注明样本范围和代表性限制；
- 行业背景与核心问题直接相关；
- 重复、低相关、来源失效和无法定位的材料已筛掉或单独列出；
- 明确未解决缺口、禁写内容、来源角色和下一步；
- 材料包、来源清单和抓取失败/重试状态使用同一版本号。

材料多不等于合格。只要关键事实仍无法复核，任务应为 `material_blocked` 或 `returned`，不能用长摘要掩盖缺口。

## 六、退回、补证和换题

- **补证**：核心问题成立，只缺一两个可定位事实；文章组指定缺口，抓爬任务最多按既定重试策略补一次。
- **缩小题目**：材料支持不了原范围，但能支持更窄的人物、作品或关系问题；必须由文章组重新确认题卡版本。
- **换题**：核心事实不可复核、风险不可接受、重复且没有新角度，或没有足够正文材料。旧任务关闭并记录原因，新题必须新建 topic_id，不在原任务上偷换方向。
- **停止抓取**：核心事实够用、关键材料类别已覆盖，后续结果主要是重复或低相关内容。此时必须交包，不以“再搜一点”延迟。

同一缺口补证一次仍不成立，不能无限换关键词；改为缩小、换题或关闭。

## 七、爆款库分级

| 等级 | 条件 | 用途 |
|---|---|---|
| `candidate` | 材料包完整，有具体冲突和可写性 | 供文章组选题和写作 |
| `adopted` | 已被文章组采用并完成成稿 | 记录标题、稿件版本和实际反馈 |
| `validated` | 有同口径平台、时间窗、样本量及曝光/阅读/完成/互动或收益数据，且能与同类比较 | 才能作为经验升级依据 |

“看起来像爆款”、外部案例高阅读或单次用户喜欢只能进入 `candidate`，不能直接写成已验证公式。案例库必须保存来源、适用题材、失败边界和数据缺口。

## 八、回交与写作审核

材料包回交时文章组确认：核心问题、可用材料、来源角色、禁写项和缺口。写作时标题候选必须绑定材料证据和首屏兑现位置；正文不把来源自证、审稿语气和抓爬过程写给读者。

成稿审核至少检查：标题和正文回答同一问题；首屏开始兑现；每段新增信息；事实、观点和推断分开；观众观点没有被夸大；当前版本路径和哈希一致。文章组可接受 `CONTENT_READY` 内容交付，R8 治理和发布授权另行判断。

## 九、每次任务必须留下的记录

`topic-card.json`、`crawl-task.json`、材料包、来源审计、筛选/淘汰记录、失败与重试状态、回交记录、标题/正文证据绑定、最终审核和结果回填。所有文件绑定 `topic_id`、版本、时间和 SHA-256；不覆盖旧版本。

每次关闭时分开报告：内容结果、来源缺口、事实未验证项、抓爬重试要求、文章表现数据和爆款库升级等级。

## 十、常用协作服务

以下服务用于辅助判断和整理，不改变文章组 controller 的选题、交付和发布权限。

### 1. 流程咨询：状态卡住时如何处理

**需要提供**：`topic_id`、当前状态、最近一次交付文件、失败原因、已尝试次数。

**处理顺序**：

1. 先确认是否同一 `topic_id`、版本和 run；不同批次不得混用状态。
2. 判断卡点属于材料不足、来源失败、重复题、风险阻断、证据哈希不一致还是文章组未接收。
3. 只执行对应动作：补证一次、缩小题目、换题、修复引用或关闭任务。
4. 检查下游状态：前置状态未通过时，不能把下游改成 `material_ready`、`CONTENT_READY` 或已验证爆款。
5. 记录 `decision`、`reason_code`、负责人、时间和下一步。

**常见处理**：

- `approved` 后抓不到关键事实：保持 `researching`，记录失败来源；达到重试上限后转 `material_blocked`，由文章组决定缩小或换题。
- 抓到很多摘要但没有正文定位：不算 `material_ready`，筛掉或回到补证。
- 材料包已交但文章组未确认：保持 `material_ready`，不能自行进入 `writing`。
- 文章写完发现标题无证据：退回标题/材料，不用换词绕过检查。
- 当前稿件哈希变了：重新生成绑定证据，旧报告留在历史记录。

### 2. 模板设计：生成 `topic-card.json` 或 `crawl-task.json`

**topic-card.json 最小字段**：

```json
{
  "schema_version": "topic-card-v1",
  "topic_id": "topic-YYYYMMDD-001",
  "version": 1,
  "status": "precheck",
  "article_group_owner": "",
  "object": {"work_or_person": "", "event": ""},
  "core_question": "",
  "target_reader": "",
  "article_type": "作品评论",
  "conflict_or_contrast": "",
  "reader_benefit": "",
  "freshness": {"mode": "same-day", "reason": ""},
  "historical_dedupe": {"same_work": "pass", "same_event_cluster": "pass", "near_title": "pass", "new_angle": ""},
  "material_requirements": ["正文事实", "行业背景", "观众反应", "复核事实"],
  "out_of_scope": [],
  "risk_tags": [],
  "acceptance": {"min_concrete_support_types": 2, "opening_support_required": true},
  "deadline": "",
  "decided_by": "",
  "decided_at": ""
}
```

只有文章组确认 `status=approved` 后，才能据此创建抓爬任务。

**crawl-task.json 最小字段**：

```json
{
  "schema_version": "crawl-task-v1",
  "task_id": "crawl-YYYYMMDD-001",
  "topic_id": "topic-YYYYMMDD-001",
  "topic_version": 1,
  "status": "researching",
  "owner": "",
  "objective": "为已确认的文章问题准备可复核材料",
  "required_materials": {
    "body_facts": [],
    "industry_context": [],
    "audience_reactions": [],
    "cross_check_facts": []
  },
  "source_constraints": {"discovery_is_proof": false, "raw_html_as_writer_input": false},
  "stop_conditions": ["关键事实可复核", "至少两类具体支撑", "后续结果主要重复"],
  "retry": {"max_attempts_per_source": 1, "state": "not_started"},
  "deliverables": ["material-pack.json", "source-audit.json", "screening-log.md", "gap-list.md"],
  "created_at": "",
  "due_at": ""
}
```

**字段规则**：`topic_id` 必须与选题卡一致；换题必须新建 ID；`required_materials` 不得写成泛化关键词；来源必须含定位、抓取时间和证据角色；观众反应必须写样本范围；失败来源不能静默删除。

### 3. 审核检查：材料包是否达到 `material_ready`

审核按四层输出：

| 检查层 | PASS 条件 | 不通过处理 |
|---|---|---|
| 题目一致性 | 材料仍回答原 `core_question`，没有抓爬过程换题 | `returned:topic_drift` |
| 事实可复核 | 关键事实有来源、发布时间/抓取时间和原文定位 | `material_blocked:unverified_claim` |
| 内容可写性 | 至少两类具体支撑，一类能进入首屏 | `returned:insufficient_material` |
| 边界与筛选 | 事实/观点/推断分栏；重复、低相关、失效来源有记录 | `returned:screening_incomplete` |

审核输出固定包含：`verdict`、逐项 `checks`、合格材料数、淘汰材料数、来源失败数、缺口、禁写项、建议动作和审核人。任何关键项 `FAIL` 都不能标记 `material_ready`；一般缺口可以标为 `material_ready_with_gaps`，但必须交文章组决定是否写作。

### 4. 角色模拟：处理常见争议

**场景 A：抓爬任务说“搜到另一个更热的话题，直接换吧”**

文章组：原题是否仍可写？如果可写，继续原题；如果不可写，抓爬任务提交 `return_reason`，由 controller 新建选题卡。不能在原 `topic_id` 下替换对象。

**场景 B：文章组说“先写，事实以后再补”**

抓爬任务：关键事实和标题承诺没有证据，不能进入正常写作；可以提交 `material_blocked` 和缺口清单，不能以热榜摘要代替。

**场景 C：找到很多评论，能不能写“网友都在说”**

审核：先分单条、同类观点和平台趋势，标样本量与时间；无法代表整体时改成“部分评论提到”或不写。

**场景 D：材料完整但题目和历史稿重复**

文章组：检查是否有新事实、新场景、新关系或新问题。没有就关闭；有则记录对比路径和 `override_reason`，再决定是否继续。

**场景 E：标题很刺激但材料只支持普通描述**

文章组：降低标题承诺或退回补证；不得添加未经证实的“封杀、抑郁、出圈、真实动机”等词。

### 5. 风险识别：灰色地带与操作建议

| 灰色地带 | 风险 | 操作建议 |
|---|---|---|
| 热榜排名被当成事实热度或内容价值 | 标题夸大，正文空泛 | 热榜只作发现信号，另找可写冲突和材料 |
| 平台标签被当成观众共识 | 以少数评论代表整体 | 写清样本和限制，区分评论层级 |
| 旧稿事实沿用到新文章 | 当前事实失效 | 动态事实重新核验，保留时间锚点 |
| 标题换词后声称新选题 | 跨批重复 | 比较对象、事件簇和核心问题；无新角度退回 |
| 来源很多但都转述同一原文 | 虚假多源 | 标记同源转载，寻找独立来源 |
| 材料包写入作者推断 | 事实与观点混淆 | 分栏并标证据等级，推断不得伪装事实 |
| 敏感普通人故事带来高点击 | 隐私、司法和猎奇风险 | 先过风险门；高点击不构成复制理由 |
| 文章已写完才发现关键缺口 | 返工或事实越界 | 标题和首屏先做证据绑定，缺口前置暴露 |
| “爆款概率”被当成承诺 | 追求夸张和填充 | 作为假设记录，发布后用同口径数据验证 |
| 文章组和抓爬任务同时改题卡 | 版本冲突 | 只允许 controller 建新版本并记录原因 |

**风险处理原则**：能通过补来源解决的补证；能通过缩小范围解决的缩小；涉及不可接受风险、无法复核事实或实质重复的关闭/换题。不能用免责声明掩盖证据缺口，也不能用机器 `PASS` 代替编辑判断。
