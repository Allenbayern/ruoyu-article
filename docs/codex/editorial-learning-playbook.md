# 若雨随影文章组写作经验与任务导向

更新：2026-09-11。本文是项目执行说明，不替代 Vault 内容边界、机器契约或发布授权。

> 若雨随影不是把影视新闻写长，而是借一个当下影视话题，写出观众愿意聊天、站队和转发的人物处境、关系冲突与现实情绪。

## 1. 选题从谈资出发

观众不一定关心抽象社会问题，但会关心：这个人物为什么这样选？这段关系为什么让人纠结？这个动作为什么像自己？这部老作品为什么今天还值得重看？影视新闻只是入口，文章价值落到人物、关系、选择、命运和现实映射上。

文章组目标是爆款概率优先，不为完成数量平均分配选题。日常默认两篇 Markdown 成品；材料不足时补证、换题或少交，不用弱题凑数。

每个候选先填写：明确读者、具体对象、核心问题、冲突或反差、可核验材料、读者收益、当前触发或常青理由，并检查历史同作品、同事件簇和相近标题。删掉今天的新闻节点后仍没有价值的题目，不进入写作。

## 2. 标题在正文之后包装

标题不是写作方向，也不是文章价值的预先承诺。发现层可以保留
`title_skeleton` 作为热榜/搜索信号，历史记录可以做标题近似去重，但这些内容不能
进入写作 brief、材料验收或正文输入。`reader_question` 是文章要回答的问题，
`reader_takeaway` 只能在成稿复核后填写。

正文先进入 `body_draft.md`，通过四项内容复核后才创建 `title_pack.json`。标题包最多
三条，也可以一条或零条；每条都必须引用现有正文 locator 和来源 locator。标题包只有
`selected`、`return_article`、`return_material` 三种结果；标题选定后还要生成绑定标题包
哈希的 `title-pack-review.json`。标题需要新增事实时回到正文复核或材料验收，标题阶段不
自动补写。

《小城之春》从“1948年的爱情为什么今天还会让人讨论”改为“入围多伦多：相爱的人，为什么还要留分寸”，是把泛问题落到关系选择。《披荆斩棘2026》从“打工人精神状态最容易出圈”改为“王传君部落发疯，像下班后的你吗”，是去掉未经证明的热度判断，补上节目、人物群体、动作和代入。两个例子只说明方向，不证明点击率规律。

## 3. 正文先回答读者问题

开稿前只锁定对象、阅读问题、冲突、证据需求和解释机制，不锁定标题。正文要让读者
在没有 H1 的情况下仍识别对象、问题、解释和判断。首段必须用具体事实、场面或动作
开始；每个主要段落必须新增事实、场面、机制或判断。成稿复核后的
`reader_takeaway` 必须能回到正文 locator，相关事实还要能回到来源 locator。

标题包装只检查既有正文是否支持标题中的对象、动作、关系和事实，不反向要求正文补段。
标题复核只消费标题包和已有证据；标题和正文组合成 `delivery.md` 后，再做最终复核。

## 4. 正文要有材料，不只摆姿态

至少提供多种真实支撑：权威来源事实、具体人物/场面/动作、可追溯观点、由事实支持的分析，必要时标明猜测。每段应新增事实、动作、归属观点或有依据的分析；连续几段重复“真实”“共鸣”等判断，说明材料或主线不够，应补证、收窄或换题，不靠人生道理凑字数。

推荐结构：事实入口 → 人物或关系冲突 → 具体材料 → 现实代入 → 回到具体人物、作品或选择的可讨论判断。公众号版本要有明确影视对象、稳定判断、完整证据链和可收藏/转述的内容，不能变成泛社会评论或娱乐快讯。

## 5. 事实、观点和发现信号分开

热榜、标题、平台标签只能发现选题，不能证明观众普遍喜欢、已经出圈、人物真实动机、作品一定成功或某种情绪代表所有人。当前事实查权威来源；观众观点追溯评论上下文，单人表达不写成“网友都认为”。来源和证据放后台，正文保持自然，不写成审稿报告，不暴露内部核验过程。

新片、新节目和新闻按当前权威来源核验；老片分析围绕作品材料，不强行编造新闻由头。不能用未经证实的封杀、抑郁、热度或因果制造刺激标题。

## 6. 开稿最小检查

- 这篇到底在聊谁、哪段关系或哪种选择？
- 删掉今天的新闻节点后，文章还剩什么价值？
- 正文前 20% 是否已经出现具体对象、事实或场面？
- 读者看完后能不能用一句话转述给朋友？
- 每个主要段落是否确实增加信息，而不是换词复述？

## 7. 获得感写作闸门

2026-09-11，用户用微信对标稿指出：要的是有内容、读完有获得感的文章，不是把标题问题用不同句子再说一遍。对标篇的共同点是先钉死一个具体对象，再把对象讲清楚，例如演员年龄和剧照、原著口碑和预告气味、衣服长短和身份。它们不是更好的通稿，是读者能转述的文章。

动笔前先写下 3 条「读者读完能转给别人的硬信息」。写不出 3 条，就补材料或换切角，不准用关系感悟、标题复述、「不是A是B」填篇幅。

每段只新增一类信息：人名和身份、动作顺序、场面物件、制作数字、可核验争议。写完问一句：删掉这段，读者会少知道一件事吗？不会就删。

正文里的问题，用机制、场面或物件回答。禁止把问题改写成解释腔，例如「这不是后来才发生的转折」「靠的不是名分，是位置」「从前的婚约不能再用，眼前的日子还得过」。出品名单、奋力求生、按姓氏笔画、定档套话同样不进正文。标题只能在正文通过后从这些已成立的内容中包装出来。

字数服从材料。材料够就写够，不够就短。禁止为了凑 1000 字灌水。对标微信文章的信息密度，不对标它们的夸张判断，例如「一万个放心」「收视要爆」「网友都认为」。

微信正文通常抓不到全文时，仍以可核验事实包为准；参考篇标题只用于识别对象，不作为事实证据。不把对标篇的未核验情节、口碑或结局写进当前稿。

## 8. 修改、交付与效果记录

先修材料、主线和正文增量，再润色句子；标题只在正文通过后包装。同一问题修订一次仍不成立，就回到缺失材料或选题决策；不要继续换词直到检查变绿。交付时分别报告内容质量、爆款概率判断、事实风险和未验证项；爆款概率是可检验假设，不是保证。

沿用两篇、Markdown、1500–2200 通常目标及 1000–2700 接受带。`CONTENT_READY` 只有在标题选定、`title-pack-review.json`、最终复核和当前交付文件都通过后才产生；R8 治理和发布授权另行报告，不代发布。正文一旦改动，旧标题包立即失效，必须重新做内容复核；标题改动则只重做标题复核并更新交付文件、证据和 SHA-256。

发布后如能取得同口径曝光、点击、完读、转发、收益和 RPM，再按题材记录中位数和样本量。单篇偏好、模型评分和外部爆文不能直接升级为长期规律。
