## 三、图片交付形态（2026-10-14 定稿）

**根因**：微信公众号编辑器只认自家图库（`mmbiz.qpic.cn`）的图片。粘贴含本地路径（`images/x.webp`）或浏览器解析出的 `file:///Users/.../Desktop/...` 绝对路径的 HTML，微信一律抓不到 → 全篇碎图；换浏览器或换复制方式都无法救回。

**定稿流程**（渲染器默认 `embed_images=False`，出现非 http(s)/base64 图片路径即渲染报错）：

1. `wechat/body.html` 交付时**零 `<img>`**，每处插图保留居中灰字「`▲ 图注`」行作为**插入锚点**；
2. `wechat/image-gallery.html` 按正文出现顺序列出全部配图（序号 / 文件名 / 格式尺寸 / 对应锚点 / 文件位置）：
   - **静态图内嵌 base64**（file:// 下 canvas 不被污染）→ 点「📋 复制这张图」后到编辑器锚点处 `Ctrl/⌘+V`，由微信自行上传入图库；
   - **动态 GIF 保留相对路径并明确标注**「必须用编辑器『图片 → 上传』选择文件」，因为走剪贴板只保留一帧、会丢动画；同时回指用户原始文件名便于在本地文件夹取件；
3. 人工在编辑器内把光标点到对应「▲ 图注」上方粘贴/上传，图文归位。

**渲染开关**（run 级 `wechat-config.json`，缺省即定稿默认值）：

| 开关 | 定稿默认 | 说明 |
|---|---|---|
| `include_cover_card` | `false` | 顶部封面大卡（Mode B 停用） |
| `include_top_follow` | `false` | 文首名片式关注条 |
| `embed_images` | `false` | `body.html` 是否内嵌本地图片（仅留档预览可开） |

实际生效开关会写入 `wechat/wechat-manifest.json` 的 `render_flags`；契约层按该记录校验对应 run（老 run 无此记录时按其历史标准校验，不做新标准回溯判定）。
