# 写作前待核清单（controller 2026-09-25 定，repo-operational）

来源：2026-09-25 controller 指示——"遇到你拿不准的信息，你可以罗列出来让我选择人工审核。
这样你拿到确定信息，写出的文章也更好看。" 当天先在 `runs/2026-09-25/hot-viral-review/`
内落地为实样（[待核清单_人工审核表.md](/home/allen/Projects/ruoyu-film-daily/runs/2026-09-25/hot-viral-review/待核清单_人工审核表.md)），
本文件把它固化为规则。诊断依据见
[门禁与写作方法诊断.md](/home/allen/Projects/ruoyu-film-daily/runs/2026-09-25/hot-viral-review/门禁与写作方法诊断.md)。

## 1 它解决什么问题

现状下 agent 遇到"这条我拿不准"只有两条路：**写短/回避**（稿子变干——1000 字出头的成因之一），
或**照写**（然后被 L2 判 `blocker`/`major`，整轮返工）。**没有第三条路：把不确定项交给人裁决。**

实证（游本昌稿，2026-09-24 公众号）：全文 5,791 CJK，其中**只有 4 条强断言拿不准**——
1 条可核、1 条口径冲突（妻子患癌，"4 年"被写成"十余年"）、1 条无来源（剃度出家）、
1 条与既有报道冲突（"封杀二十年"）。**若起草前有这张表，4 条改口径或删除即可，其余 5,000 字不受影响。**

## 2 何时必交

**任何进入 brief / 起草的选题，动笔前必须先交待核清单。** 与既有门禁的关系：

- 它**不替代** `killer_stance` / `sensory_anchors` / claim 账本，只是补上"不确定性出口"这一环；
- 它不是选题设立（选题仍走两道门：搜刮 → 候选池 → controller 圈题）；
- 清单**被勾选 ≠ 发布授权**。

## 3 清单格式（每条七字段）

| 字段 | 含义 |
|---|---|
| `id` | `U01` 起编 |
| `item` | 我要写进正文的那句话/那个数 |
| `uncertainty` | 缺什么证据、和什么冲突 |
| `recommendation` | 我倾向的写法（允许是"我建议不写"） |
| `alternatives` | A / B / C 备选口径 |
| `blast_radius` | 改这个口径会动到正文哪一句/哪一段 |
| `blocking` | `yes` = 裁决前不得起草该篇；`no` = 可按默认规则处理 |

数量控制在 **3–6 条**。只列真正拿不准的，不要拿已核实项充数；已核实项另列
"已替你核完（不用你决定）"清单。

## 4 默认规则（关键）

- **未被勾选/未回答的项，一律按最保守口径处理**：不写、降级为归属表述、或加来源归属。
- `blocking: yes` 的项未裁决前，**不得起草该篇**（可先写其他槽位）。
- 裁决结果必须回填到 run 内（`content-fidelity.json` 的待核字段，或 run 根下的
  `pending-review-sheet.json`），供 L2 与后续批次复查；**不允许只存在于对话里。**

## 5 与 L2 的关系

L2 复核时把清单当作对照物：**清单里声明"不写/已降级"的点，若出现在正文中即为 finding。**
这比事后逐句猜"这条有没有来源"更省成本，也让复核有明确的靶子。
