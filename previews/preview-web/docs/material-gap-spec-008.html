1. 结论先行

• 缺的两类材料都能抓到：同口径数据层（四部片票房/预算/片长/评分）用中文维基 infobox 一次拿全；采访层（主创原话）在署名记者现场稿里有独家内容。

• 但"多抓几篇"会产生假独立来源：本篇通稿被至少三家平台改写式转载，逐句重合 0%、事实点重合约 100%。若不检测，就会把同一篇稿当成两个独立来源（这正是 daily-008 里 c03 单源风险的放大版）。

• 同口径数据一补上，原稿的核心命题需要微调：姜文四部片的票房不是"一部比一部"单调下滑，而是 6.59 亿 → 5.147 亿 / 5.82 亿平台期 → 0.92 亿断崖。原稿若只靠"拧巴"的形容词，读者拿不到这条硬信息；补上后文章反而更稳。

• 补料后的容量估算：约 2600–3000 字（"每个论点有独立来源"口径）；硬上限 3500+（含单一自媒体数据的部分）。这已经明显高于"现有四份来源"的 2000–2200 字天花板。

3. 抓取侧改造要求（提案，未执行）

3.1 新增来源独立性检测：fact_point_overlap

• 只用字符串重合判断会漏（实测逐句重合 0%、事实点重合 100%）。

• 方法：把新来源切为"事实点"（人名+身份、时间+数字、动作、地点、原话），与已有来源做事实点集合重合率；重合率 ≥60% 且无新增事实点 → 判 syndicated_rewrite，不计入独立来源数。

• 结果写入 source-manifest.json 的 independence 字段：primary_interview / independent_angle / syndicated_rewrite / syndicated_fragment / single_source_data / reference_table。

• min_distinct_scene_sources 只统计前两类。

3.2 任务卡与材料验收新增字段

``yaml required_source_roles: [media_report, commentary, data_reference] # 新增 data_reference material_requirements: min_scene_items: 8 # 具体场面/桥段条数 min_distinct_scene_sources: 2 # 且必须是独立来源（见 3.1） min_comparable_data_points: 4 # 同一对象的多时点/多作品同口径数据 min_primary_quotes: 2 # 主创/当事人原话（署名、带场合） ``

不达标时：任务卡不得把 reference_shape 定为 viewing_commentary，字数带按低一档执行（见 length-policy-proposal.md §3.1b）。

3.3 优先抓取顺序（本期的经验）

5. 未验证与风险

• 维基 infobox 数据为二手汇总，正式交付前应对"票房/预算"字段回查一次权威口径（片方通稿或猫眼/灯塔公开页）；本次仅作容量测算；

• e04（网易号）逐日数据为单一自媒体来源，未交叉复核；

• e01 的"镜头数 4700+"来自记者稿转述，未见片方原始物料；

• 本次只测了 art-001 一题；art-002（还珠题材）的场面层是否同样只能拿到转载，需要单独测一次。
