7.1 顺带发现的新门禁问题：扩写触发"来源自证"红线

v2400 首次提交时 style_gate 报 2 个 error，全部来自同一句"据潮新闻的报道"——命中红线规则 source:据…报道 与 source:媒体+稿件词（正文禁止来源自证/元话语）。删去这半句后全绿（2640 字，仅剩 1 条 info：上映日期断言）。

这条经验值得写进 playbook：正文可以点名评论者或机构作为说话人（"上观新闻的韩浩月认为…"，008 原稿与三版扩写均通过），但不能写"据某媒体报道/据某平台统计"。补料越多、越容易触发。

7. 待定结论

初步可确认的三点：

• 原稿的短不是"没材料"，是"没用材料"——150 条可用条目只用了 21 条（14%）；扩写版用同一批材料写到 1895 字，仍然零来源外事实。

• 但"加字"不等于"加事"——v1800 多出的 863 字里，新增场面只有 2 条，其余是判断与引语的重新编排；容量测算员据此判定扩写"部分注水"，我先前的"有效扩写"说法过宽，已修正。

• 原稿的真正硬伤比字数更早出现：三处"结论"引用的是来源标题而非正文证据；两节各 111 字是提纲式压缩；content-fidelity.json 里 5/13 段位登记为"收束未知项"（无新增信息）。

据此，字数不是独立变量：字数上限由"场面层"供给决定，而这一期场面层 80% 依赖单一匿名来源。要写到 2000 字以上且不注水，必须先补 c03 之外的独立场面来源与四部片同口径数据。
